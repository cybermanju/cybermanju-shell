# Native NVIDIA lifecycle follow-up — corrected patch 19

## Change

`kernel/comps/nvidia-platform/src/worker.rs` adds `NvidiaInterruptWorker`, a safe owner pairing one fresh transactional MSI-X lease with one `DeviceWorker`. Its only constructor is fallible `prepare(&NvidiaDeviceResources, vector_count, callback)`: it checks sleepable/current-task context before touching resources, acquires a fresh masked lease through `NvidiaDeviceResources::prepare_msix`, then starts the actual callback worker. There is no arbitrary-guard constructor, so callers cannot adopt a pre-activated lease or foreign handlers; fields remain private and `register_handler` routes callbacks to this worker's `WorkSignal`. If task creation fails, lexical drop of the unactivated, handler-free guard invokes the existing rollback. Shutdown contracts remain unchanged: preflight sleepable/non-self context; mask MSI-X, call the required device-source quiesce closure, synchronously retire IRQ callbacks, check DMA/PBA state and restore the prior disabled MSI-X state; then close/drain the worker. MSI-X errors retain the guard for retry, and successful guard closure is remembered so repeated worker shutdown remains safe. `WorkerError::Msix` preserves the underlying OSTD error.

The closure is deliberately mandatory. There is no NVIDIA-specific source-mask/acknowledge sequence or RM/GSP implementation here; MSI-X masking is not described as stopping a GPU's interrupt source. The wrapper is native lifecycle glue, not a GPU probe, interrupt hardware validation, or full driver. A real owner must still quiesce hardware and RM/source producers before shutdown; this CPU-only evidence does not claim that device-level work was done.
